# 隐私与脱敏（技能文件 / 报告）

本技能要能复制给任何人用，所以**文件里不能残留某一台机器的个人数据**。运行时给用户看的真实路径是必要的，但写进技能、报告、提交、聊天记录之前必须脱敏。

## 技能文件里禁止出现

- 用户名、主机名、Windows 账户目录（`C:\Users\<具体名字>`）
- 绝对个人路径（如某个工作区、某个盘的深层目录）
- 具体盘符（`C:` / `D:` / `E:`）——示例统一用 `X:\` 或 `<DATA_DRIVE>:\`
- 日期/时间戳（会暴露机器状态；需要时写“当前”）
- PID、进程路径、文件哈希（除非是一次性的排查结果，且已确认不含隐私）
- 凭据：`.credentials.yaml`、API key、token、cookie、登录态
- 会话内容：`sessions/*`、`db.sqlite`、日志正文、附件/截图
- **对话历史、聊天记录、提示词、Agent 会话 id、工具调用记录**：不要写进技能文件、示例、测试脚本或报告
- 用户目录快照、备份清单里的真实文件名（可能含项目/客户名）

## 允许的占位符

| 真实值 | 写进文件时 |
|---|---|
| `C:\Users\<你>` | `%USERPROFILE%` |
| `C:\Users\<你>\AppData\Local` | `%LOCALAPPDATA%` |
| `C:\Users\<你>\AppData\Roaming` | `%APPDATA%` |
| `E:\DSHData` | `<DATA_DRIVE>:\DSHData` 或 `X:\DSHData` |
| 目标数据目录 | `<TARGET_ROOT>` |
| 应用数据根 | `<APP_HOME>` |
| 应用名/进程名 | `<APP_NAME>` / `<PROCESS>` |

## 报告/交付时怎么脱敏

- 用 `Detect-Platform.ps1` 的 `displayRoot`，不要用 `dataRoot`。
- 路径替换顺序：先替换更长/更具体的路径（`DSH_HOME`、`LOCALAPPDATA`），再替换 `USERPROFILE`；否则会被提前压成 `%USERPROFILE%` 后匹配不上。
- 只报“体积/文件数/检查项/结论”，不报“用户名/主机名/具体项目名”。
- 需要贴路径时，写 `<DATA_DRIVE>:\...` 或 `%USERPROFILE%\...`。
- 不把 state 文件原文贴出去（里面有真实路径）；只贴 state 文件的位置描述。

## 运行时例外

- 脚本在**本机终端里**输出真实路径是必要的（用户要照着操作）。
- 一旦要把输出放进文档、聊天、issue、提交，先按上表脱敏。
- `Detect-Platform.ps1 -Json` 同时提供 `dataRoot`（执行用）和 `displayRoot`（分享用）；AI 报告用后者。

## 提问方式（学 ZCode 的“一次问清”）

不要连环追问。把需要的输入一次列全，每项带默认值/推荐值：

1. **目标精确路径**（例如 `X:\DSHData\.dsh`；本地 NTFS、非 OneDrive、尽量短）
2. **应用什么时候可以完全退出**（窗口 + 托盘 + 后台；如果 Agent 跑在该应用里，说明 Cutover 要用户手动执行）
3. **旧数据保留策略**（默认保留，用户明确确认后才清理）

平台不明确时，先问平台；其他问题不要拆成多轮。用户答不齐就停在这一步，不猜。
