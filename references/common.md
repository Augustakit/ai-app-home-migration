# 公共规则（所有平台共用）

本文件只写跨平台的硬规则；平台特有的数据根、锁、收尾方式见 `platform-dsh.md` / `platform-zcode.md` / `platform-workbuddy.md`。

## 开工前的四条保守规则

1. **先问平台，一次只迁一个。** 用户要求同时迁两个及以上时拒绝：数据迁移必须一个平台完成、核验通过后再做下一个。
2. **默认整目录。** 迁 `.dsh` / `.zcode` / `.workbuddy` 这类应用数据根本身，不默认挑单个文件/子目录；只搬子目录会让根目录仍是真目录，以后新增内容继续落在原盘。
3. **用户说不清数据在哪，先请求只读搜索权限。** 只在用户同意后检查环境变量、常见数据目录、进程；不猜路径、不先写任何文件。
4. **备份默认保留，核验通过后及时清理。** 迁移后要逐文件核对；发现缺失/不一致先从退路补齐，全部通过并获用户确认后，按覆盖闸门清理退路，不要长期占空间。

## 防御性设问

真正执行前，一次性向用户确认：范围（整个根）、目标精确路径、应用可关闭时间、备份/清理策略、失败回滚预期。再把“将复制什么 → 到哪里、预计大小、保留什么退路、不会删除什么、回滚命令”复述一遍，得到明确“开始”后才动手。不要用“应该可以”代替确认。

还可以补问这些风险点（有则处理，无则记录“已确认无”）：

- 目标盘是否 BitLocker/加密、权限受限、外接或可移动？
- 应用是否有后台服务/多个账户/同步客户端正在使用数据目录？
- 源盘剩余空间是否足够保留退路直到核验完成？
- 用户是否接受“迁移期间应用完全不可用”和“失败时用退路回滚”？
- 是否只迁移整个数据根（默认），而不是某个子目录/文件？

## 阶段模型

所有迁移都拆成五个阶段，平台差异只影响每个阶段能不能在“应用运行中”做：

| 阶段 | 做什么 | 失败时 |
|---|---|---|
| **Discover** | 只读盘点：数据根、体积、内部链接、进程/锁、目标盘空间 | 不改任何文件，停止 |
| **Prepare** | 复制。ZCode 允许运行中预拷贝；DSH / WorkBuddy 一般要求应用已退出 | 源不动；目标/临时目录保留供检查 |
| **Cutover** | 最后一次同步/校验 → 旧目录改名留退路 → 原位置建 Junction | 立即回滚改名/Junction，源保留 |
| **Verify** | 平台专属核验，统一输出 `PASS / WARN / FAIL` 与退出码 | 保留退路，不删任何数据 |
| **Cleanup** | 用户明确确认后，按覆盖闸门清理退路 | 闸门不通过就保留退路 |

## 不可协商的规则

1. **先证明，再切换。** 体积、锁、空间、复制一致性、Junction 指向，全部用命令证明；不靠“看起来没问题”。
2. **应用没完全退出，不做 Cutover。** 窗口、托盘、后台进程都算。Agent 自己跑在目标应用里时，Cutover 必须交给用户在应用外执行。
3. **旧目录只改名不删除。** 统一命名 `<原目录>.migbak`（DSH 脚本当前用 `.dshbak`，保持兼容）；删除必须是用户明确确认后的独立动作。
4. **目标必须是本地固定 NTFS 盘。** 网络路径、可移动盘、OneDrive 一律拒绝；源/目标不能是盘根，不能互相嵌套。
5. **`robocopy` 必须带 `/XJ`**，退出码 `0–7` 正常、`>=8` 才是失败。
6. **复制后逐文件比对**（相对路径 + 大小；必要时静态文件哈希），不能只比“总数 + 总字节”。
7. **源树内部先扫 reparse point。** 内部有链接/Junction 时 `/XJ` 会静默跳过，导致缺数据；非零就停下来先处理。
8. **判断 Junction 用 `LinkType` / `ReparsePoint`**，不要用 `$i.Length`（任何目录都返回 1）。
9. **删 Junction 用非递归方式/`rmdir`**，绝不 `Remove-Item -Recurse`；删退路前做覆盖闸门，先删链接再删内容。
10. **空间验证用磁盘剩余空间差**，不用递归目录大小（会穿透 Junction）。
11. **默认不删除任何数据**；清理退路必须显式开关 + 用户确认。
12. **一次只迁移一个应用/一个平台**，不要并行跑两个迁移脚本。

## PowerShell 5.1 约束（Windows 自带）

- 脚本必须 **UTF-8 with BOM**（无 BOM 时 PS 5.1 按 GBK 解析，中文语法会炸）；已有 BOM 不要重复补。
- `.cmd`/`.bat` 必须 **CRLF + 纯 ASCII**（含中文注释时容易半行执行）；中文交互放在 `.ps1` 里。
- 长路径：PS 5.1 的 `Get-ChildItem -Recurse` 对 >260 字符路径**静默漏文件**。脚本内枚举统一用 `.NET` 的 `\\?\` 前缀（`[System.IO.Directory]::EnumerateFiles`）；不要改回 GCI。
- 必填参数不要用 `Mandatory=$true`（`-File` 模式会转成交互提示，非交互场景挂起）；缺参就显式报错并给示例。
- `-WhatIf` 只用于预检分支；不要让只读 cmdlet 继承 `-WhatIf`（CIM/PSDrive 会返回空值造成假失败）。
- 脚本里判断管理员：用 `WindowsPrincipal.IsInRole`，不要用 `net session`。

## 安全闸门

- **进程守卫**：Cutover 前检查目标应用进程；发现就停止，提示用户完全退出。
- **目标检查**：必须为空或不存在；不是盘根；不在源树内；不是链接。
- **覆盖闸门**（清理退路时）：退路里的每个文件都必须在目标盘存在且大小一致（静态文件建议加 SHA256）；通过后才允许删。
- **回滚**：保留 state 文件（源/目标/退路/环境变量旧值）；失败时优先恢复旧目录和 Junction，不删目标数据。
- **备份生命周期**：默认保留退路 → 逐文件核对目标 ↔ 退路 → 有差异先从退路补 → 再核验 → 用户确认后清理。不要在核验前删退路，也不要长期保留到用户忘记。

## 逐文件核对与补齐

- 迁移前复制校验：相对路径集合 + 每个文件大小（静态文件可加哈希）。
- 迁移后核验：拿**退路本体**和目标比对，不要拿“经 Junction 读到的源”和目标比对（两者读的是同一份数据，是假校验）。
- 发现缺失/大小不一致：先补齐（从退路复制到目标），再重新核验；不要带差异继续用。
- 只允许在“目标已确认是本次迁移产物、退路可读”时执行补齐；不能反向覆盖退路。

## 核验合同

所有平台的 `Verify-*.ps1` 输出统一风格：

```
[PASS] ...
[WARN] ...
[FAIL] ...
结果：N PASS / M WARN / K FAIL
```

- 退出码：`0` 无 FAIL，`1` 有 FAIL（需要处理）。
- WARN 必须逐条解释；不能拿“没有 FAIL”替代人工确认。
- 核验是只读的；需要写探针时用明显的临时文件名并当场删除。

## 隐私与可移植性

**技能文件里不写用户个人数据**：不写用户名、主机名、日期、盘符、绝对个人路径、实际会话内容、凭据。所有示例用 `%USERPROFILE%`、`<DATA_DRIVE>:\...`、`X:\...`、`<TARGET_ROOT>` 等占位符。运行时输出给用户的真实路径可以保留，但报告/文档/提交内容必须先脱敏。详见 `privacy.md`。
